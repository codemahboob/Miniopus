# Single-page store (Flipkart mobile product page + 3-step checkout)

Plain HTML/CSS/JS plus one tiny serverless function. No framework, no build step,
**zero npm dependencies**. Page weight is about 0.6 MB, mostly the photos.

The page copies Flipkart's mobile product page. **Buy at ₹…** opens a 3-step checkout:
**Address → Order summary → Payment** (Razorpay online payment, or Cash on Delivery). Online payments are created and verified on the server; the Razorpay secret is never sent to the browser.
When the customer places an order, `api/send-order.js` emails you
the full order and address through [Resend](https://resend.com). You ship it yourself.
If the customer typed an email, they get a confirmation too.

## Files

| File | What it does |
|---|---|
| `config.js` | Store defaults: name, price, MRP and delivery days |
| `index.html` | Product page + the 3 checkout steps + order-placed screen |
| `style.css`, `script.js` | Look and behaviour |
| `api/send-order.js` | Validates the order, re-prices it on the server, sends the emails |
| `images/` | Placeholder photos: replace with yours |

## Deploy

1. Push to GitHub: `git init && git add . && git commit -m "store" && git branch -M main && git remote add origin <your-repo-url> && git push -u origin main`
2. On [vercel.com/new](https://vercel.com/new) import the repo. Framework preset: **Other**. No build command.
3. In **Settings → Environment Variables** add:
   - `RESEND_API_KEY`: from resend.com
   - `TO_EMAIL`: the inbox that receives orders
   - `FROM_EMAIL`: `onboarding@resend.dev` for testing, or an address on your verified Resend domain for production
4. Deploy, then place a test order. Every push to `main` redeploys.

> With `onboarding@resend.dev`, Resend only delivers to the email you signed up with, and customer confirmation emails will not send.
> Verify your own domain in Resend to email customers.

## Make it yours

- **Product, price and reviews:** edit them in the admin dashboard. The backend reads the saved product name and price from Supabase when that table is configured; otherwise it falls back to `config.js`.
- **Photos:** replace files in `images/` (square, about 900 px). Add or remove `<img>` lines inside `#slides` in `index.html`.
- **Title, description, offers, FAQ:** edit the text in `index.html`.
- **Ratings and reviews:** the numbers and the three reviews are **samples**. Replace them with real ratings and reviews from your own customers before going live.
- **Online payments:** configure `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` in Vercel environment variables (see Razorpay setup below). Keep the secret out of all browser files. COD continues to work without Razorpay keys.
- **Pack sizes:** `packs` in `config.js` (1, 2, 3 units by default).
- **Search box and cart icon** in the header copy Flipkart's look. Search is decorative on a one-product store.
- **Policies:** `privacy-policy.html` and `return-refund.html`, with your support email.

## Sales dashboard (admin.html)

The dashboard is available at `/admin.html` and reports orders/revenue for today, 7, 30, 90 days, and one year. To store and display real orders, configure Supabase and these Vercel environment variables: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, and a strong `ADMIN_DASHBOARD_PASSWORD`. Do not expose the service-role key in browser code.

Run this SQL in the Supabase SQL Editor to create the order table:

```sql
create table if not exists public.store_orders (
  id bigint generated by default as identity primary key,
  order_id text not null unique,
  customer_name text not null,
  phone text not null,
  address text not null,
  landmark text,
  city text not null,
  state text not null,
  pincode text not null,
  quantity integer not null default 1,
  payment_method text not null check (payment_method in ('COD','PREPAID')),
  total_amount numeric(10,2) not null,
  order_status text not null default 'PLACED',
  created_at timestamptz not null default now()
);
alter table public.store_orders enable row level security;
```

The API uses the service-role key only on the server. Set the environment variables in your hosting provider and redeploy. Orders placed before this database is configured will not be retroactively included. The dashboard totals are placed-order values; prepaid status must be verified in your payment app before dispatch.

## DeoDap API setup (admin dashboard)

The admin dashboard now has a **DeoDap API setup** section with official contact links. It is intentionally marked **Not connected** and does not collect credentials yet: public-facing information confirms a dropshipping service, but the API endpoint/authentication/order-creation contract for this account has not been verified. Do not enter a normal DeoDap password as an API key.

Before implementing automatic order forwarding, ask `dropshipping@deodap.com` or your DeoDap account manager for:
- API documentation and whether API access is enabled for your plan
- authentication method and credential rotation process
- product/SKU lookup or mapping requirements
- order-create endpoint and COD/prepaid support for your plan
- order status, cancellation, tracking and retry/idempotency rules

After the official API contract is supplied, implement the connection through server-side API routes only. Keep API secrets out of browser JavaScript and never forward an order until the customer order has been saved and the supplier accepts it. DeoDap's dropshipping website is https://dropshipping.deodap.com/.


### Product settings editor

The admin dashboard includes **Product page settings** for product name, description, main photo URL, selling price, MRP, rating, rating/review count, and three displayed review cards. These values are stored in Supabase and fetched by the storefront through `/api/store-config`. Razorpay is configured separately through Vercel environment variables, not through the admin dashboard.

Create this table in the Supabase SQL Editor (keep Row Level Security enabled; do not add public policies):

```sql
create table if not exists public.store_settings (
  key text primary key,
  value jsonb not null,
  updated_at timestamptz not null default now()
);
alter table public.store_settings enable row level security;
```

The serverless functions use `SUPABASE_SERVICE_ROLE_KEY` on the server only. Do not add this key to frontend code. After creating the table and deploying, open `/admin.html`, sign in, and save your product settings. Use a direct HTTPS image URL or a path like `/images/photo-1.jpg`.

## Razorpay setup (manual)

1. Sign in to your Razorpay account and open **Account & Settings → API Keys**.
2. Generate keys in **Test Mode** first.
3. In Vercel, open this project → **Settings → Environment Variables** and add `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET`. Use the exact Test Mode values, then redeploy.
4. Test the checkout with Razorpay test payment details. Confirm the order email says **PAID via Razorpay** only after verification succeeds.
5. Before going live, generate **Live Mode** keys in Razorpay, replace both Vercel variables, and redeploy. Never commit the secret to GitHub or expose it in browser code.

The checkout uses Razorpay Standard Checkout. Razorpay payment success is signature-verified server-side and the payment amount/order is checked against the server's configured product price. For COD, no Razorpay payment is attempted. Order email delivery still requires the Resend environment variables described above.
